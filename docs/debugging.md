# Debugging

This project uses SEGGER RTT for day-to-day logs and J-Link GDB for source-level debugging.

---

## SEGGER RTT

RTT is the preferred logging path because it does not require a UART console.

### Get the RTT address

After building the CR8 firmware, extract the `_SEGGER_RTT` symbol from the map file:

```bash
./extract_rtt_addr.sh Debug/rzv2h_px4_freertos.map
```

The script prints the address and writes it to the requested output file when provided. It looks for the `_SEGGER_RTT` symbol in the linker map generated by the CR8 build.

### Open RTT Viewer

Use SEGGER J-Link RTT Viewer with the extracted address:

- Target: `R9A09G057H44_R8_0`
- RTT buffer: `rtt_0`
- J-Link server: configured in [`.vscode/launch.json`](../.vscode/launch.json)

If RTT does not connect, confirm that:

- The board is powered and halted under J-Link
- The firmware was built from the current tree
- The RTT symbol exists in the map file

## GDB Debugging

Launch the CR8 debug configuration from VS Code with `F5`.

The active launch configuration is in [`.vscode/launch.json`](../.vscode/launch.json) and uses:

- `cortex-debug`
- `servertype: jlink`
- `JLinkGDBServer`
- `Debug/rzv2h_px4_freertos.elf`

Useful checks:

- Make sure the J-Link probes the `R9A09G057H44_R8_0` core
- Use the `Debug` build so symbols and line information are available
- If the target state looks stale, rebuild and relaunch instead of attaching to an old session

## Log Extraction

### CR8 firmware logs

PX4 flight logs are written to the SD data partition under:

- `/drone-data/cr8_data/log/`

This is the location to inspect after a flight or bench test.

### Typical workflow

1. Build the firmware.
2. Deploy it to the board.
3. Fly or bench test the vehicle.
4. Copy `.ulg` files from `/drone-data/cr8_data/log/`.

### Notes

- RTT is still useful for early boot and live diagnostics.
- PX4 logging must be enabled in the firmware configuration.
- If logs are missing, check that the SD data partition is mounted and writable.
